Under the hood

How it was done safely

This was surgery on a 6,000-line file that runs the warehouse, so the method was the point. Every edit was an anchored replacement whose anchor had to be unique, all 18 of them applied in memory and written once at the end — so a failed check costs nothing instead of leaving the file half-edited.

The new markup reuses the same element IDs wherever behavior survives, which meant the battle-tested code was never rewritten at all: drawers, the number pad and its Zoho receipt, print, the picker gate, radio, the beacon with its 45-minute memory and quiet-when-someone-is-present rule, optimistic picks that survive a stale tick, the accordion rules. Component styling was carried across mechanically with the old token names aliased, so nothing had to be re-themed by hand.

Everything that worked, still works

The Direct accordion, one-job tabs, shelf-first rows, 44px ✓ Pick, dual shelves as two places, pack-size receding, the honest "+N past the cap", bands that count the whole order, the shelf count with its Zoho receipt, and the beacon. Nothing earned was spent.

The loop earned its keep

Six defects caught before you saw them

  • The note was truncating instead of the order id — backwards. The id now yields first; the exception always leads.
  • A deviance row crushed its own SKU — the prose now gives the lane to the chips.
  • The phone bar overflowed and the tabs collided — the phone sheds ornaments and keeps the list.
  • Metric cards overflowed their own borders — a grid child refuses to shrink unless you tell it to.

And two that only the LIVE render could find — the mock could not lie about them: the wall was printing the spreadsheet's raw status cell inside its own status line, and its staleness thresholds disagreed with the tool's, so the same pipe would have read "stale" on one screen and "idle" on another. Both fixed; all three surfaces now report identically. New rule: always finish by rendering the live page, not just the mock.
